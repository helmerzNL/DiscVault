# v26.9.69 — Scan & add, cleaned up

_Released: 2026-08-23_

## Highlights

Two things about adding titles that made the scanner feel clunky are fixed, and a
box set now scans to the edition it actually is.

Scanning is now a fresh start every time. Previously the Scan & add form kept the
previous item's fields, so a second scan could return the *previous* title until
you cleared it by hand, and reopening **Add** after a save still showed the item
you had just added. Now a scan searches by that barcode alone, and a successful add
clears the form on its way to the library.

Separately, a box set whose barcode had been moved to a different box set in the
catalogue could resolve to the box set it was moved *off* — reported as
`786936826951` opening a 4K "Avengers Assembled: Complete 4-Movie Collection"
instead of the Blu-ray "Marvel Cinematic Universe: Phase One" it now belongs to.
The lookup now always resolves to the box set that currently owns the barcode.

## 🐛 Bug fixes

- **A scan searches by that barcode alone** ([#706](https://github.com/helmerzNL/DiscVault/issues/706),
  [#708](https://github.com/helmerzNL/DiscVault/pull/708)). A camera scan overwrote
  only the barcode field and left the previous item's title, year, TMDB ID and IMDB
  ID in place. The lookup sends all of those together, so it matched on the stale
  title and returned the previous title until the field was cleared by hand. A scan
  now clears those identity fields first. The Format selector is left as you set it —
  it is a disc preference, not an identity.

- **The Scan & add form resets after a successful add**
  ([#706](https://github.com/helmerzNL/DiscVault/issues/706),
  [#708](https://github.com/helmerzNL/DiscVault/pull/708)). Adding a single title
  jumps to it in the library; the form now clears the barcode, the other search
  fields and the rendered result on the way, so reopening **Add** starts clean. The
  batch workflow is unchanged — it checks the line off and stays to advance to the
  next barcode.

- **A box-set barcode resolves to its current owner**
  ([#707](https://github.com/helmerzNL/DiscVault/pull/707)). The catalogue is synced
  as a stream of in-place deltas, and each entity only cleared its own lookup rows.
  When a barcode was reassigned from one box set to another, the box set that lost it
  was often not re-sent, so its stale `barcode → box set` row survived and the lookup
  could return it. An entity's own barcode is now exclusive — claiming it removes any
  other box set's or release's claim on the same barcode — and the lookup prefers the
  most recently updated owner. Member-disc barcodes are untouched: a disc legitimately
  belongs to its standalone release and to every box set that contains it. A force-full
  re-index action was added to rebuild the index and drop any row already stuck.

## ⚠️ Upgrade notes

**No operator action is strictly required.** An existing deployment upgrades unchanged.
No Compose file and no `.env.example` was changed, no database migrations run, and
there are no new dependencies.

**One optional repair step.** The box-set fix makes new catalogue deltas self-healing,
but a server that already holds a stale lookup row keeps it until it rebuilds its index
generation. To clear it immediately after upgrading, trigger one re-index:

- `POST /api/next/plugins/movievault_v2/jobs` with body
  `{"entrypoint":"sync_index","forceFull":true}`, or
- the manual equivalent: `UPDATE movievault_v2_sync_state SET cursor = NULL;` then run
  a normal MovieVault index sync.
