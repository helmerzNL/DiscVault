# v26.9.41 — Statistics you can read, and act on

_Released: 2026-08-14_

## Highlights

The statistics page is rebuilt. It counts works instead of discs, splits movies
from TV, lets you narrow it to a period, draws each chart as a pie or as bars,
and turns every slice into a link — click a genre, a director or an actor and
the library opens filtered to those titles.

Alongside it: the Import Center's pressing picker now says when the barcode is
already certain instead of always doubting it, and DiscVault keeps itself out of
search engines and AI training corpora by default. Two self-hosted instances had
turned up in Google.

## ✨ Features

- **The statistics page, rebuilt** ([#657](https://github.com/helmerzNL/DiscVault/pull/657)).
  New charts across the board and a period selector — last month, last year, all
  time — that scopes the figures to what was added in that window.

- **Genres and decades as pie charts, on a palette that stays readable**
  ([#659](https://github.com/helmerzNL/DiscVault/pull/659)). The colours are
  checked for contrast against each other and against both the light and the dark
  theme, so neighbouring slices never blur into one.

- **Every chart switches between a pie and bars**
  ([#660](https://github.com/helmerzNL/DiscVault/pull/660)). A pie answers "how is
  this split", bars answer "which is bigger than which", and no single form
  answers both. Long lists collapse to the leading entries with "Show all" to
  open them up.

- **Statistics count works, and separate movies from TV shows**
  ([#665](https://github.com/helmerzNL/DiscVault/pull/665)). A box set of six
  discs is one film, not six, so a shelf-heavy title no longer outweighs the rest
  of the collection. A type selector puts movies, TV shows or both in view.

- **Click a genre, a director or an actor to see those films**
  ([#666](https://github.com/helmerzNL/DiscVault/pull/666)). Every slice, bar and
  row in the statistics view is a link into the library, filtered to exactly what
  the chart was counting. "Show in library" does the same for a whole chart.

- **The pressing picker says when the barcode is already confirmed**
  ([#658](https://github.com/helmerzNL/DiscVault/pull/658)). "Which pressing is
  this?" used to claim the barcode was unconfirmed on every route into it. That is
  true when the film was found by title and false when it was found by barcode —
  there the code is right and only the pressing is open, because a reissue carries
  the barcode of the edition it replaces. MovieVault now states which case it is,
  and the picker says so. It also shows one poster under the film line: two 4K
  pressings of one film share a cover, so a poster per row would be the same
  image repeated. An older MovieVault says nothing, and DiscVault then keeps the
  cautious wording — the behaviour against an older server is unchanged.

- **DiscVault keeps out of search results and AI training corpora**
  ([#661](https://github.com/helmerzNL/DiscVault/pull/661)). Nothing had to be
  misconfigured for an instance to be indexed: the app shell and the public routes
  answer an anonymous request, so a crawler that reaches the host has a document
  to index whether or not the collection behind it is gated. Three layers now
  cover it — a `/robots.txt` that disallows every crawler, `X-Robots-Tag: noindex`
  on every response plus the matching `<meta name="robots">`, and a 403 for known
  search-engine, AI, SEO and link-preview user agents. `/robots.txt` and
  `/api/next/health` always answer, so a health check never reads a live instance
  as down. This is not a security control — a user agent is self-reported — and
  the README says so.

- **A pinned poster is recognisable as pinned on the sync wire**
  ([#663](https://github.com/helmerzNL/DiscVault/pull/663)). Sync contract 1.29
  §4.8b: a client has to tell a poster the user deliberately pinned apart from one
  a provider merely supplied, because the first may replace an existing poster and
  the second may not. `poster_url` carries both assertions in one field and cannot
  express the difference. DiscVault already held the fact under another name
  (`{kind}_locked`), so this is a rename on the wire rather than a new fact, and
  the two spellings are folded onto one stored truth in both directions.

## 🐛 Bug fixes

- **The director and actor charts were empty or wrong**
  ([#662](https://github.com/helmerzNL/DiscVault/pull/662)). They asked the
  database for a column that does not hold what they wanted. A PostgreSQL smoke
  test now covers the top-credits queries, so the same class of mistake fails in
  CI instead of on the page.

- **The statistics view sat tighter against the screen edge than every other
  view** ([#664](https://github.com/helmerzNL/DiscVault/pull/664)). It did not use
  the shared page spacing.

- **One format was listed several times, once per spelling**
  ([#667](https://github.com/helmerzNL/DiscVault/pull/667)). "Blu-ray", "Blu Ray"
  and "BluRay" arrive from different sources and different imports and were
  counted as three formats, splitting one bar into three shorter ones. Each format
  now has a single spelling, applied where the statistics are read and where
  MovieVault field corrections are written.

- **An HD DVD was badged as a DVD**
  ([#668](https://github.com/helmerzNL/DiscVault/pull/668)). The badge matched on
  the string ending in "DVD", which HD DVD does. They are different formats and
  are now badged as such.

## ⚠️ Upgrade notes

**No operator action is required.** An existing deployment upgrades unchanged.

One new environment variable exists, and it does **not** have to be added:

- `DISCVAULT_BLOCK_CRAWLERS`, default `true`. It is read with a built-in default,
  so an instance that never sets it gets the crawler blocking automatically. It is
  documented in `app/.env.example` and `app/deploy/next/.env.example` (commented
  out, since the default is the wanted value), and the shipped Compose files map
  it as `DISCVAULT_BLOCK_CRAWLERS: ${DISCVAULT_BLOCK_CRAWLERS:-true}` on
  `next-api` — the only service that serves pages.
- **Only if you deliberately want an instance to be findable**: set
  `DISCVAULT_BLOCK_CRAWLERS=false` in your `.env`, and — if you run a Compose
  override of your own rather than the shipped file — add the mapping line above
  to your `next-api` service, or the variable will not reach the container.

Note that blocking is now the default where previously there was none. An
instance you *wanted* in Google will drop out of the index unless you opt out.

No database migrations, no new backend dependencies, and no manual reload
required.

`app/frontend/`, CI bumped the patch once more. Production already had this fix,
so nothing about it is new to a user upgrading.
