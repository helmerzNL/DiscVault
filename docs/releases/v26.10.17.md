# v26.10.17 — Sign in with your identity provider, score filters and scheduled syncs

_Released: 2026-10-17_

## Highlights

This release lets a self-hosted instance sign people in through **OpenID Connect**
(Pocket ID, Authentik, Keycloak and the like), and gives the Library the tools to
act on the external score: filter on it, require a minimum number of votes behind
it, sort and export it, and find the films that have none. Instance-defined custom
fields become readable on the detail page and importable from a file column. The
admin area gains a **Scheduled tasks** tab — a built-in daily backup and an
automatic Jellyfin and Plex library sync.

Alongside that, the imports stopped losing data (quoted CSV fields, nested CLZ XML,
disc counts, TV seasons), a save no longer erases a film's custom field values, a
sync can no longer write into a deleted row and then report success, and the origin
backfill that did nothing in 26.9.98 now actually runs.

**Read the upgrade notes before deploying** — this release runs four database
migrations, and existing libraries need one manual backfill before the new vote-count
filter returns anything.

## ✨ Features

- **Sign in with an OpenID Connect identity provider**
  ([#781](https://github.com/helmerzNL/DiscVault/pull/781),
  [#782](https://github.com/helmerzNL/DiscVault/pull/782),
  [#783](https://github.com/helmerzNL/DiscVault/pull/783),
  [#785](https://github.com/helmerzNL/DiscVault/pull/785)). DiscVault can now act as
  an OIDC relying party: a sign-in button for the configured provider, and controls
  to link or unlink that identity on an existing account. It is **off by default** —
  an instance without the new variables behaves exactly as before. The flow is
  durable rather than in-memory (migrations 093–095): authorisation transactions are
  stored server-side, their nonce is stored only as a hash, and each one is bound to
  the browser that started it, so a callback replayed from another browser is
  refused. A login method is protected from being removed while it is the account's
  only usable way in. For a provider that publishes private in-cluster endpoints
  (a Kubernetes Service, say), `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` names
  the exact HTTP origins allowed for token and key requests; the issuer and the
  browser-facing authorisation endpoint stay HTTPS-only. Failures are written to the
  audit log as `auth.oidc_failed` with a safe error code, never with a secret or a
  token. Setup is described in `app/deploy/next/README.md`; the callback is
  `/api/next/auth/oidc/callback`.

- **Filter the Library on the external score**
  ([#765](https://github.com/helmerzNL/DiscVault/pull/765)). Requested on
  [#719](https://github.com/helmerzNL/DiscVault/issues/719): find films to watch that
  are generally well rated. The Advanced panel gains a **Score** group with a lower
  and an upper bound on the 0–10 axis the score pill already uses; it saves into a
  smart filter and a box set is matched through its members. A stored zero means
  *not scored* (TMDB sends `vote_average` 0.0 for a title nobody voted on), and a film
  with no score is out of the result for either bound — "no score" is not "a low
  score". The panel says how many loaded films have no score, so an empty result on a
  library whose metadata was never fetched does not read as a broken filter.

- **Require a minimum number of votes behind a score**
  ([#767](https://github.com/helmerzNL/DiscVault/pull/767),
  [#766](https://github.com/helmerzNL/DiscVault/issues/766)). A 10.0 from three votes
  outranked an 8.4 from twelve thousand, and a physical collection is full of
  obscure pressings with few votes. The vote count is now stored beside the score
  (`movies.rating_votes`, migration 092), shown on the detail page next to the score,
  and offered as a **Minimum votes** floor in the Advanced panel. `NULL` means "never
  asked" and `0` means "asked, nobody voted" — the column has no default precisely so
  an existing library does not claim TMDB answered it. A dedicated **Vote counts**
  card with a backfill button is added to the admin metadata screen. TMDb 1.9.0 and
  OMDb 1.1.0 emit `ratingVotes`.

- **Sort the Library on the score, and export it**
  ([#775](https://github.com/helmerzNL/DiscVault/pull/775)). Sortable score columns
  in the Library list and a score column in exports.

- **Unscored films are discoverable**
  ([#778](https://github.com/helmerzNL/DiscVault/pull/778)). The score filter
  deliberately leaves out films that have no score, so the Advanced panel gains a
  **Score availability** choice to show exactly those films. It is replayed with the
  tag filters when a smart filter is applied.

- **Several tags in the advanced filters, matching any or all**
  ([ab984fb](https://github.com/helmerzNL/DiscVault/commit/ab984fb),
  [3dad7e5](https://github.com/helmerzNL/DiscVault/commit/3dad7e5),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). The tag dropdown that was
  reported missing is back, and a filter now takes more than one tag with a choice
  between "any of" and "all of". Selections and the mode are kept in saved smart
  filters, and older single-tag filters are migrated.

- **A film's custom field values are shown on its detail page**
  ([#763](https://github.com/helmerzNL/DiscVault/pull/763),
  [#762](https://github.com/helmerzNL/DiscVault/issues/762)). Custom fields shipped
  in 26.9.98 filterable, sortable and exportable, but readable only by opening the
  edit form. A subsection in the Collectors tab now shows them. Archived fields are
  shown when they carry a value (archiving means "no new input", not "invisible"),
  and a film with no values renders no empty heading.

- **Import a file column into a custom field**
  ([#764](https://github.com/helmerzNL/DiscVault/pull/764),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). The import mapping can
  now target `custom:<key>`, and the Import Center lists the defined fields. Values
  fill only what the film does not already have; a cell that is refused is counted
  and named in the import summary instead of ending a run of thousands of rows.

- **Choose a film's box set, vault or collection in the edit form**
  ([#809](https://github.com/helmerzNL/DiscVault/pull/809),
  [#810](https://github.com/helmerzNL/DiscVault/pull/810)). The Collectors section of
  the edit panel gains the Library's Container picker — one choice across box sets,
  vaults and collections, with "+ New …". Choosing another container moves the title;
  "No container" unlinks it. Applied on Save through the existing membership
  endpoints.

- **Scheduled backup and library sync**
  ([#814](https://github.com/helmerzNL/DiscVault/pull/814),
  [#815](https://github.com/helmerzNL/DiscVault/pull/815),
  [#812](https://github.com/helmerzNL/DiscVault/issues/812),
  [#813](https://github.com/helmerzNL/DiscVault/issues/813)). A built-in scheduler
  in the worker: a **Schedule** tab under Backup creates a backup automatically
  (interval, skip when nothing changed since the last scheduled backup, keep the
  newest N), and a new **Scheduled tasks** admin tab syncs the Jellyfin and Plex
  libraries every N hours, optionally followed by the watched-history sync attached to
  the admin who saved it. The interval counts from the last scheduled run. Saving one
  tab never resets the other's schedule.

- **CLZ "Nr Discs" is recognised as the disc count**
  ([#795](https://github.com/helmerzNL/DiscVault/pull/795),
  [#792](https://github.com/helmerzNL/DiscVault/issues/792)). CLZ Movies writes each
  release's disc count under a column literally named "Nr Discs"; neither that nor
  "Nr of Discs" was an alias, so imported rows read as "disc count unknown".

## 🐛 Bug fixes

- **A film's save erased its custom field values**
  ([#761](https://github.com/helmerzNL/DiscVault/pull/761)). The edit form read the
  stored values from `detail.customValues`, which the detail payload never carries
  (it is `detail.movie.custom_values`), so every input rendered empty. An empty input
  is sent as "delete this value", so opening a film, correcting its title and pressing
  Save erased every custom value on it — with no error and no log line. Both the
  accessor and the payload key are now pinned by a test.

- **"Fill in origin data" did nothing**
  ([#760](https://github.com/helmerzNL/DiscVault/pull/760),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). Reported as "I pressed
  the button and nothing seems to happen" with 1,488 films still missing origin. No
  backfill job had ever succeeded: it passed the plugin to the execution context as a
  frozen dataclass where a dict is expected, and every job with a non-empty batch died
  before its first TMDB request. Three silences hid it — the confirmation was
  overwritten by "Metadata jobs loaded.", the job list never showed the origin jobs,
  and the counters were read before anything was queued. Jobs now carry the ids they
  own (an unfillable first hundred no longer starves the rest of the library), a
  missing, disabled or unconfigured TMDb plugin fails with a readable reason, the
  counter and the selector are one query shape again, and the card reports the queue,
  the last run (filled in / no answer / failed) and warns when TMDb is older than 1.8.0.

- **A sync could write into a deleted row and report success**
  ([#759](https://github.com/helmerzNL/DiscVault/pull/759)). On three of the four
  routes that reach `apply_movie_upsert` with an id on a tombstoned row, the payload
  was written into the dead row, the server answered `status: applied`, and the film
  vanished again on the next delta. Re-adding could never work once a client-entity
  mapping was stored. The tombstone is now always cleared when the server decides to
  apply, and the tombstone lookup gains a media-type veto and a minimum digit length so
  synthetic import placeholders cannot match unrelated box-set members.

- **A backend outage looked like a broken delete button**
  ([#756](https://github.com/helmerzNL/DiscVault/pull/756)). "Backend connection
  unavailable" on a delete or on a login after a restart was one outage reported as
  two broken buttons: the service worker replayed cached reads indistinguishably from
  live ones, so the first thing to fail was always a write. A replayed read is now
  labelled, the shell raises a banner while it is looking at cached data, and a write
  failure says whether this device has no network or cannot reach DiscVault.

- **The rating stars rendered as vertical slivers**
  ([0dca089](https://github.com/helmerzNL/DiscVault/commit/0dca089)). The half-step
  was made by cutting each star into two clipped buttons, and the flex gap cancelled
  the negative margin that joined them. Each star is now drawn whole with transparent
  hit targets on top, and dragging along the row sets the rating on touch as well. The
  rating's accessible label is now a sentence in all 29 locales.

- **The content-rating flag painted under the age**
  ([b1a79b7](https://github.com/helmerzNL/DiscVault/commit/b1a79b7)). The hero
  backdrop rule was a descendant selector, so it also caught the flag inside the
  content-rating pill and stretched it to the pill's edges.

- **A box set filed inside a collection rendered an empty tile**
  ([#816](https://github.com/helmerzNL/DiscVault/pull/816),
  [#811](https://github.com/helmerzNL/DiscVault/issues/811)). A container's cover lives
  in an `entity_media` row, never in `metadata->>'poster_url'`, which was the only
  place the collection items query looked.

- **Jellyfin sync failed on newer servers**
  ([#814](https://github.com/helmerzNL/DiscVault/pull/814),
  [#813](https://github.com/helmerzNL/DiscVault/issues/813)). Newer Jellyfin refuses
  the legacy `?api_key=` query parameter and the sync sent no auth header. The key now
  goes in the `Authorization` / `X-Emby-Token` headers, out of the URL, and HTTP and
  JSON failures become readable job errors. Jellyfin plugin 1.0.2.

- **The app shell now follows the browser's language**
  ([#808](https://github.com/helmerzNL/DiscVault/pull/808),
  [#807](https://github.com/helmerzNL/DiscVault/issues/807)). The browser language is
  negotiated when the shell loads.

- **Existing provider scores and vote counts are refreshed**
  ([#774](https://github.com/helmerzNL/DiscVault/pull/774)). A current provider rating
  can replace a populated value without a global metadata overwrite, including stale
  zero scores; provider priority and the other field policies are unchanged.

- **`disc_count` was never saved, and an edit wiped it**
  ([#803](https://github.com/helmerzNL/DiscVault/pull/803),
  [#801](https://github.com/helmerzNL/DiscVault/issues/801),
  [#802](https://github.com/helmerzNL/DiscVault/issues/802)). `movies.disc_count` had
  no working writer on any path: the import writer never selected it, the sync upsert
  computed it and never bound it, and the edit path bound `None` — wiping the value on
  every edit. All three now follow the fill-only pattern, and an edit that says nothing
  about discs keeps the existing value. A CLZ XML export's `<nrdiscs>` element could
  not match the multi-word alias either; matching now also compares alphanumerics only.

- **Nested CLZ XML values are imported**
  ([#796](https://github.com/helmerzNL/DiscVault/pull/796)).

- **Quoted CSV fields survive an import**
  ([#797](https://github.com/helmerzNL/DiscVault/pull/797)). CSV files are parsed
  through newline-aware streams, and an unreliable sniffed double-quote setting is
  overridden while the supported delimiters are kept.

- **The import preview now predicts what the import does**
  ([#798](https://github.com/helmerzNL/DiscVault/pull/798),
  [#791](https://github.com/helmerzNL/DiscVault/issues/791)). The preview and the
  writer each carried their own hand-written copy of the barcode → identifier →
  title+year matching and had drifted: the writer skipped format-incompatible rows,
  the preview did not, and the preview had no notion of two rows in one batch naming
  the same film — hence 460 previewed creates against 447 actual. Both now call one
  `resolve_import_identity_match`, and the preview keeps an in-memory pool of earlier
  items in the batch.

- **TV seasons keep their identity during import**
  ([#793](https://github.com/helmerzNL/DiscVault/pull/793)). A TMDb or IMDb id can name
  a whole series, so a candidate that disagrees with the import on both title and year
  is the wrong season and not a match.

- **Empty import metadata suggestions are handled**
  ([d0f81aa](https://github.com/helmerzNL/DiscVault/commit/d0f81aa)).

- **An OIDC identity could sign in exactly once**
  ([#800](https://github.com/helmerzNL/DiscVault/pull/800),
  [#799](https://github.com/helmerzNL/DiscVault/issues/799)). The identity lookup
  returned `oidc_identities.id` under the name `id` and the caller spent it as a user
  id, so every later login raised `identity_already_linked`.

- **A failed OIDC callback left its one-time code reusable**
  ([#805](https://github.com/helmerzNL/DiscVault/pull/805),
  [#804](https://github.com/helmerzNL/DiscVault/issues/804)). The `used_at` mark ran in
  a savepoint on a shared connection, so exactly the attempts that failed rolled the
  mark back while the audit event was still recorded. The lookup now commits on a
  connection of its own.

- **Private OIDC back-channels are supported**
  ([#785](https://github.com/helmerzNL/DiscVault/pull/785)). See the OIDC feature above.

## ⚠️ Upgrade notes

**Back up first.** This release runs four database migrations (092–095). Take a backup
before upgrading. Migrations 094 and 095 clear `oidc_auth_transactions` (in-flight OIDC
sign-ins only); an instance upgrading from 26.9.98 has none, because OIDC is new here.

**Run the vote-count backfill after upgrading, or the new vote floor matches nothing.**
Vote counts are captured when a film's metadata is fetched, so films already in your
library have none until the backfill fills them in. Open **Admin → Metadata**, find the
**Vote counts** card and press **Fill in vote counts**. It asks TMDB for the bare record
rather than running a full metadata refresh. Until then a vote floor leaves those films
out, and the Library says how many.

**Check the plugins actually upgraded.** Plugins run from the writable install directory
and are only replaced when the bundled copy is strictly newer. TMDb **1.9.0** and OMDb
**1.1.0** emit `ratingVotes`; an instance left on the old versions will run the backfill
and store nothing. **Admin → Plugins** shows the installed versions.

**Jellyfin users:** the Jellyfin plugin is now 1.0.2 and authenticates with headers. A
server that already worked keeps working; a newer one that refused `?api_key=` syncs
again.

**Scheduled tasks are off until an admin turns them on.** Nothing is scheduled by default:
enable the backup schedule under **Admin → Backup → Schedule** and the library syncs under
**Admin → Scheduled tasks**. Saving a backup schedule needs `admin.backup`; the Jellyfin and
Plex schedule is available with `admin.backup` or `digital_sources.sync`.

**OIDC is off until you configure it.** An existing deployment needs no change. To enable
it, set `DISCVAULT_OIDC_ISSUER`, `DISCVAULT_OIDC_CLIENT_ID` and
`DISCVAULT_OIDC_CLIENT_SECRET` together (a partial configuration is rejected), and register
`https://<your-host>/api/next/auth/oidc/callback` with the provider. The callback origin is
derived from the first value of `RP_ORIGINS`. Keep the client secret in the untracked
`.env` or a secret store.

**No manual reload is required.** No preference is overridden, and nothing that was on is
turned off.

### Deployment files

- **`app/.env.example`, `app/deploy/next/.env.example`, `app/deploy/next/docker-compose.yml`
  and `app/docker-compose.next.yml` changed.** Five optional variables were added, all
  empty by default, which keeps OIDC disabled. Add them to your `.env` only if you enable
  OIDC:

  ```
  DISCVAULT_OIDC_ISSUER=
  DISCVAULT_OIDC_CLIENT_ID=
  DISCVAULT_OIDC_CLIENT_SECRET=
  DISCVAULT_OIDC_PROVIDER_NAME=
  DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=
  ```

  and the matching Compose mappings under the API service's `environment:` if you maintain
  your own Compose file:

  ```yaml
  DISCVAULT_OIDC_ISSUER: ${DISCVAULT_OIDC_ISSUER:-}
  DISCVAULT_OIDC_CLIENT_ID: ${DISCVAULT_OIDC_CLIENT_ID:-}
  DISCVAULT_OIDC_CLIENT_SECRET: ${DISCVAULT_OIDC_CLIENT_SECRET:-}
  DISCVAULT_OIDC_PROVIDER_NAME: ${DISCVAULT_OIDC_PROVIDER_NAME:-}
  DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS: ${DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS:-}
  ```

  A deployment that does not use OIDC keeps working untouched, with or without these lines.
  `DISCVAULT_OIDC_PROVIDER_NAME` only changes the sign-in button label.
  `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` takes comma-separated exact HTTP origins
  (for example `http://pocket-id.pocket-id.svc.cluster.local:1411`) and should stay empty
  unless the provider deliberately publishes private in-cluster endpoints.

- **No size, rate or timeout limit changed in this release**, so nothing running in front of
  DiscVault — a reverse proxy, an ingress, a CDN — needs adjusting. The OIDC callback is an
  ordinary GET on `/api/next/auth/oidc/callback`; a proxy that rewrites that path breaks the
  flow.
