# v26.9.98 — Your own data: origin, ratings and fields you define yourself

_Released: 2026-09-01_

## Highlights

This release is mostly about making the library answer questions it could not
answer before. A film now carries its **country of origin and original language**
— the film's own, not the disc's — so "show me my Japanese films" is a filter
rather than a guess. Everyone with an account gets a **personal 0.5–10 rating**
per film, shown, sorted and exported beside the external score. And the owner of
an instance can now **define their own fields** — "rip status", "shelf",
"purchase price" — which appear on the edit form, in filters, in the list columns
and in exports without a deploy.

Alongside that, the Library and the Lists module stopped losing things: a large
library no longer strands at 700 movies, the Watchlist and Watched list no longer
stop at 500 entries, sorting finally honours the Sort title, and deleting a film
now does the sensible thing with the lists it was on. The MCP server got its
statistics tools working for the first time, and `/mcp` now actually reaches an
MCP server running in its own container.

**Read the upgrade notes before deploying** — this release runs six database
migrations, and existing libraries need one manual backfill before the new origin
filters return anything.

## ✨ Features

- **Country of origin and original language, captured and filterable**
  ([#741](https://github.com/helmerzNL/DiscVault/pull/741),
  [#739](https://github.com/helmerzNL/DiscVault/issues/739)). `movies.country` and
  `movies.language` describe the *pressing* — a Dutch Blu-ray of a Japanese film
  correctly stores `NL` — so filtering on them answered a different question than
  the one people were asking. TMDB has been sending `original_language`,
  `origin_country` and `production_countries` all along and DiscVault threw them
  away. They are now stored on their own, published over sync, shown on the detail
  page directly under "Release country" and "Language" so neither is mistaken for
  the other, and offered as two filters in advanced search (combinable with the
  year range and watchlist filters, and saveable in a smart filter). Country and
  language names come from `Intl.DisplayNames` at render time, so all 250-odd
  regions work in every locale without a translation table. Nothing is backfilled
  from the release country — deriving it would have recorded the Netherlands as
  the origin of *Ran*, permanently and plausibly, for everyone owning a European
  edition.

- **An admin screen for the origin backfill**
  ([#747](https://github.com/helmerzNL/DiscVault/pull/747)). The backfill endpoints
  shipped with #741 and nothing in the app ever called them: the library said
  "{count} films have no origin data yet" and the only way to act on it was to
  issue the POST by hand. **Admin → Metadata** now carries the two counters
  (pending, and unresolvable for films with no TMDB identifier — kept separate so
  the counter can actually reach zero) and a button that queues the job.

- **A personal rating per user, on the same 0–10 axis as the external score**
  ([#741](https://github.com/helmerzNL/DiscVault/pull/741)). 0.5 to 10.0 in half
  steps, stored per user on the personal sync stream. On a shared instance the
  *owner's* score is published to anyone who may see the film and is labelled with
  whose it is; nobody else's score ever leaves its author. "No rating" is the
  absence of a row, not a zero and not a NULL, so an unrated film is never ranked
  as though it had been scored. It gets a list column (`personalRating`, sorted
  numerically with unrated last in *both* directions), an export column, and an
  optional star badge on tiles behind the `show_rating_badge_on_tiles` preference.
  The external TMDB/OMDb pill is relabelled from "Rating" to "Score" so its text
  says which of the two it is.

- **Fields you define yourself, and they behave like built-in ones**
  ([#741](https://github.com/helmerzNL/DiscVault/pull/741),
  [#742](https://github.com/helmerzNL/DiscVault/pull/742)). A new **Admin → Custom fields** tab
  defines fields by name, type and — for a list field — its choices, and reorders,
  renames and archives them; the movie edit form grows an input per live field
  built from what the server published, so a field the owner adds appears without a
  deploy. Values are typed columns rather than a JSON blob, which is what makes
  them sortable and range-searchable: text matches on substring, number and date
  offer range comparisons, boolean and select match on equality. Each field gets a
  filter clause in advanced search (saveable in a smart filter), a sortable list
  column, and an export column keyed `custom:<field-key>` that ships default-off so
  a default export stays byte-identical to one taken before this release. Renaming
  changes only the label — the key that stored values and saved filters point at
  stays put. Archiving keeps the values and keeps them matching; the confirmation
  says how many films carry one. Clients can write a value one field at a time,
  never as a set, so a phone that models three of five fields cannot silently
  delete the other two.

- **The Watchlist and the Watched list sort by title or year**
  ([#733](https://github.com/helmerzNL/DiscVault/pull/733),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). Reported as "the
  Watchlist does not sort in order of Sort-Title (or even Title)" — half right: it
  sorted on the *list* date and there was no control to ask for anything else. Both
  tabs now offer list date newest/oldest, name A–Z/Z–A and release year
  newest/oldest. The default is the order the server already returned, so nobody's
  list rearranges itself on upgrade, and the choice is remembered per browser.

- **Recording a watch takes its subject off the watchlist**
  ([#734](https://github.com/helmerzNL/DiscVault/pull/734),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). Reported as an
  oxymoron, and that is the right word: the watchlist answers "what do I intend to
  watch" and the watched list answers "what have I watched", so answering the
  second settles the first. Applied to all three routes that record a watch — a
  film, an episode, and the season button, which clears every episode of the
  season.

- **You choose whether deleting a film takes your watch history with it**
  ([#732](https://github.com/helmerzNL/DiscVault/pull/732),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). The default stands —
  history records something that happened, and deleting the disc does not un-watch
  the film — but "if I delete something, regardless of any statuses, I want it
  gone" is just as defensible about *your own* history. New
  `delete_removes_watch_history` preference on the Library tab, off by default,
  read per user rather than per actor.

- **Support DiscVault, if you want to**
  ([#740](https://github.com/helmerzNL/DiscVault/pull/740)). A voluntary Buy Me a
  Coffee invitation on three surfaces: a card on About, a quiet text link in the
  desktop sidebar, and a dialog shown once after the library has drawn (skipped on
  an empty collection and on any deep link; every exit records the ask, so it does
  not come back). The button artwork is served from DiscVault's own asset route
  rather than the Buy Me a Coffee CDN — a remote image would report every About
  page visit to a third party and break on an install with no route to the internet.

- **A rate-limited external lookup now says so**
  ([#712](https://github.com/helmerzNL/DiscVault/pull/712)). MovieVault now returns
  `provider_rate_limited` when a legacy-disc scan's external fallback source has
  exhausted its daily free-lookup quota. That is classified as its own failure kind
  rather than falling through to the generic "MovieVault could not complete this
  lookup": it was reached and replied, so it is not "unavailable", and a daily quota
  does not clear on a retry, so there is no "try again" button.

## 🐛 Bug fixes

- **A large library no longer stops loading at 700 movies**
  ([#718](https://github.com/helmerzNL/DiscVault/pull/718),
  [#715](https://github.com/helmerzNL/DiscVault/issues/715)). A 2,509-movie library
  filled to 200, then 700, then stopped for good — the first-paint snapshot plus
  exactly one hydration chunk. `library-paging.js` pages into an array the SPA
  replaces whenever it reloads its snapshot, so a page already in flight was
  appended to an array that had shrunk back to 200, leaving a hole offset paging
  cannot step back over; the next page came back fully duplicated and the anti-loop
  guard ended hydration permanently.

- **Deleted films no longer come back as black, unclickable tiles**
  ([#727](https://github.com/helmerzNL/DiscVault/pull/727),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). The length guard from
  the #715 work could not see a snapshot reset landing while the first chunk was in
  flight, because the reset restores the array to exactly the length that chunk was
  fetched against. Pages are now refused when either the loaded count or the
  snapshot epoch moved since the fetch, and ids the session itself deleted are
  purged at once and refused for the rest of the session.

- **The Library orders on the Sort title**
  ([#721](https://github.com/helmerzNL/DiscVault/pull/721),
  [#716](https://github.com/helmerzNL/DiscVault/issues/716)). A user who filled in
  Sort title across their collection saw no change at all. The server was never the
  problem — every list query already ends in
  `ORDER BY lower(COALESCE(m.sort_title, m.title))` — but the PWA re-sorted the
  hydrated rows client-side on the display title, in three independent comparators,
  throwing that order away. A supporting index for exactly that expression is added
  (migration 086); the two indexes that looked like they covered it did not, because
  an expression index serves only the exact expression it was built on.

- **A personal list no longer stops at 500 entries**
  ([#730](https://github.com/helmerzNL/DiscVault/pull/730),
  [#729](https://github.com/helmerzNL/DiscVault/issues/729)). The Lists module showed
  the first 500 entries of the Watchlist and of Watched and nothing beyond, while the
  badge kept showing the real total. The ceiling sat in four places at once — both
  entity builders, the routes and the page — so raising any subset changed nothing;
  all of them now read one `PERSONAL_LIST_MAX_PAGE_SIZE`, and the public API pair
  serving the same lists to the MCP tools is raised with them. This ends watchlist
  truncation outright (it is bounded by the collection); watch history is unbounded,
  so this raises that wall rather than removing it.

- **Deleting a film removes it from the Watchlist, and its Watched entry keeps a
  poster** ([#728](https://github.com/helmerzNL/DiscVault/pull/728),
  [#731](https://github.com/helmerzNL/DiscVault/pull/731),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). Migration 015 kept
  personal-list entries as snapshots when their movie went, which is right for watch
  history and wrong for a to-watch list — the orphan rendered as an unclickable card.
  Watchlist rows are now deleted with the movie (and each affected user's sync stream
  is told); the Watched list still keeps its entries by design. Separately, a Watched
  entry's snapshot froze whatever poster address the movie had at the time, and for
  locally stored artwork that is a route that 404s the moment the movie's media links
  are deleted — the "black poster" that was reported.

- **The Discover feed pages** ([#737](https://github.com/helmerzNL/DiscVault/pull/737),
  [#736](https://github.com/helmerzNL/DiscVault/issues/736)). `/api/next/discover`
  passed the already-read *value* of the page argument to a parser that takes an
  argument *name* and reads the request itself. It looked up an argument named after
  the value, found nothing, returned the default — and served every page as page 1.

- **The Lists sort button is no longer blank**
  ([#738](https://github.com/helmerzNL/DiscVault/pull/738),
  [#719](https://github.com/helmerzNL/DiscVault/issues/719)). Reported as "a blank
  button. I see the slight outline, so I guessed it was sort". The icon sizing rule
  was scoped to `.collection-controls`, so it reached the Library and location
  toolbars and not the Lists sort trigger, whose markup is otherwise
  character-for-character the same.

- **Bulk "add to box set" works again**
  ([#723](https://github.com/helmerzNL/DiscVault/pull/723),
  [#720](https://github.com/helmerzNL/DiscVault/issues/720)). Every bulk add returned
  `name 'actor' is not defined`: the permission check was called for its side effect
  and the actor it returns was dropped, then that never-bound name was passed on. A
  `check_undefined_names.py` gate now runs in the Postgres smoke workflow —
  `py_compile` proves a module parses, not that a line can run — and was itself
  tightened afterwards ([#726](https://github.com/helmerzNL/DiscVault/pull/726)) so a
  module-level read of an undefined name can no longer vouch for a function-level one.

- **Saving a film with custom values, and creating a custom field, no longer fail**
  ([#745](https://github.com/helmerzNL/DiscVault/pull/745),
  [#746](https://github.com/helmerzNL/DiscVault/pull/746)). Two defects in the #741
  writes. Creating a field failed with "name is required" on a form whose name box
  was filled in — six calls omitted `Content-Type: application/json`, so the body
  arrived as `text/plain`, Flask parsed nothing, and each route rejected whichever
  argument it checked first ("Nothing to update", "values must be an object", "score
  is required" were the same bug). And saving crashed with
  `'UUID' object is not subscriptable`, because the custom-values route handed a
  movie id to a permission check that takes the entity; all sixteen call sites were
  audited and this was the only wrong one.

- **The five MCP statistics tools are callable**
  ([#748](https://github.com/helmerzNL/DiscVault/pull/748)). They were advertised by
  `tools/list` and refused for every role, the owner included, naming a permission key
  that did not exist: #654 added them to the MCP server but not to the catalogue every
  call is checked against. The keys, their owner/admin/mcp_user grants and the
  statistics endpoint gate now exist (migration 091, bundled plugin manifest 1.1.0).

- **`get_top_actors` and `get_top_directors` stop 500-ing and hanging**
  ([#752](https://github.com/helmerzNL/DiscVault/pull/752)). Both read
  `/api/next/stats/personal`, which applied its defaults *after* case-folding them, so
  any caller omitting `period` or `mediaType` got
  `'NoneType' object has no attribute 'lower'`. The statistics page always sends both;
  the MCP server sends neither, so neither tool ever reached the query. The same
  endpoint also looked up exchange rates over the network inside the request with a
  transaction open, which is what made it hang.

- **`/mcp` reaches an MCP server in another container**
  ([#751](https://github.com/helmerzNL/DiscVault/pull/751)). The proxy target was
  hardcoded to `http://127.0.0.1:6090` — correct for the all-in-one image, where both
  processes share a network namespace, and the API's own loopback in every split
  deployment, including the one `app/deploy/next/docker-compose.yml` ships. It answered
  "MCP server is not reachable … Connection refused" however healthy the MCP server was,
  and no setting could move the address. `DISCVAULT_MCP_URL` now names the target.

- **Flags render next to age ratings and languages**
  ([#750](https://github.com/helmerzNL/DiscVault/pull/750),
  [#749](https://github.com/helmerzNL/DiscVault/issues/749)). Eight of the 23 countries
  the content-rating picker offers had no flag file, so the endpoint 404'd and the
  browser drew its broken-image glyph beside a perfectly fine age label — a static-asset
  404 is not an application error, so nothing logged it. Denmark and Sweden were on disk
  under *language* codes (`da.svg`, `sv.svg`) and are renamed to `dk.svg`/`se.svg`; AU,
  BR, NZ, IN, PH and MY were listed with no file and are added. A code with no file now
  renders no icon instead of a broken one.

- **Custom-field translations reached the right languages, and three catalogues lost
  borrowed diacritics** ([#743](https://github.com/helmerzNL/DiscVault/pull/743),
  [#744](https://github.com/helmerzNL/DiscVault/pull/744)). The 30
  `appAdmin.customField*` strings were written into the wrong locale files — en-US
  carried Italian, nl-NL Ukrainian, de-DE French — because an authored list in natural
  language order was zipped against an alphabetically sorted file list; 27 of 29
  catalogues shifted. No translation was lost (the mapping is a bijection) and the
  table is now keyed by locale rather than ordered, which is the structural fix. Separately,
  lt-LT used the Polish ż and dropped two š, lv-LV used the Lithuanian ų, and ro-RO used
  cedilla forms where Romanian takes comma-below.

- **A scanned barcode's confirmation status survives the response reader**
  ([#713](https://github.com/helmerzNL/DiscVault/pull/713)). The Add-flow picker chooses
  between "the film is certain, pick the pressing you are holding" and "the barcode was
  not confirmed by any of these pressings" on `barcodeConfirmed`, and the outer response
  reader ran before the per-status branch and dropped every key it did not list.

- **The TMDb plugin manifest is bumped so origin capture reaches existing installs**
  ([#741](https://github.com/helmerzNL/DiscVault/pull/741)). Plugins run from the
  writable install directory and are replaced only when the bundled version is strictly
  newer. At 1.7.1 the new code would have shipped to *new* installs and nowhere else:
  every existing instance keeps the old plugin, `filmOrigin` never arrives, the origin
  filters stay empty forever, and the backfill job reports success over a plugin that
  never returned the field. Now 1.8.0.

## ⚠️ Upgrade notes

**Back up first.** This release runs six database migrations (086–091). Take a
backup before upgrading.

**Run the origin backfill after upgrading, or the new filters stay empty.** Origin
is captured when a film's metadata is fetched, so films already in your library
have none until the backfill fills them in. Open **Admin → Metadata**, find the
**Country of origin** card and press **Fill in origin data**. It asks TMDB for the
bare record rather than running a full metadata refresh, so it takes minutes. The
two counters on that card are also the answer to "why is my country filter empty":
*Films still missing it* is what the job will fill, *Not matched to TMDB* is films
with no TMDB match, which this job cannot answer at all and which therefore never
reaches zero.

**Check the TMDb plugin actually upgraded to 1.8.0.** Plugins run from the writable
install directory and are only replaced when the bundled copy is strictly newer.
1.8.0 is what emits `filmOrigin`; an instance left on 1.7.1 will run the backfill,
report success, and store nothing. **Admin → Plugins** shows the installed version.

**Split (`app/deploy/next`) deployments must add one variable before `/mcp` works.**
See the deployment-file section below. An all-in-one image deployment needs no change.

**MCP clients: reconnect after upgrading.** The five statistics tools
(`get_collection_stats_detailed`, `get_top_formats`, `get_top_genres`,
`get_top_directors`, `get_top_actors`) gain their permissions in migration 091 and
are granted to owner, admin and `mcp_user`. Any other role that should call them
needs the `mcp.tool.*` permissions granted by hand in **Admin → Roles**.

**Devices re-sync the catalogue once.** Migration 090 schedules a one-time catalogue
republish so the two custom-field entities reach devices that have already synced —
without it a device continues from its cursor, sees neither, and reports a successful
sync while doing so. This is automatic; expect one larger-than-usual sync per device.

**No manual reload is required.** No preference is overridden, and nothing that was
on is turned off. The new tile rating badge (`show_rating_badge_on_tiles`) and both
new export columns ship **off**, so a default-selection export stays byte-identical
to one taken before this release.

### Deployment files

- **`app/deploy/next/.env.example` and `app/deploy/next/docker-compose.yml` changed.**
  Add this line to your `.env` for a split deployment:

  ```
  DISCVAULT_MCP_URL=http://next-mcp:6090
  ```

  and the matching Compose mapping under `next-api`'s `environment:` if you maintain
  your own Compose file:

  ```yaml
  DISCVAULT_MCP_URL: ${DISCVAULT_MCP_URL:-http://next-mcp:6090}
  ```

  This is the address **inside** the Docker network, so it does not follow
  `DISCVAULT_NEXT_MCP_PORT` — that one only republishes the host port. Change it only
  if you rename the `next-mcp` service or make it listen on another container port.
  Because the Compose default is `http://next-mcp:6090`, a deployment using the
  shipped Compose file keeps working without touching `.env`; one with a hand-written
  Compose file must add the mapping or `/mcp` keeps refusing.

- **`app/.env.example` changed: `MCP_PORT` is removed.** It was never read by
  anything — the MCP server's listen port is passed on its command line, and a
  Compose deployment republishes it with `DISCVAULT_NEXT_MCP_PORT`. Delete it from an
  existing `.env`. Leaving it in place breaks nothing; it simply does nothing.

- **No size, rate or timeout limit changed in this release**, so nothing running in
  front of DiscVault — a reverse proxy, an ingress, a CDN — needs adjusting.
