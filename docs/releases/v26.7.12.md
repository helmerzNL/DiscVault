# v26.7.12 — MovieVault covers in the PWA & duplicate-disc rescan fix

_Released: 2026-07-31_

## Highlights

Promotes the `release/v26-beta` line into `main`, bringing MovieVault cover
artwork to the PWA/web app for barcode scans, box-sets and the library — a set
of behaviours that previously only worked in the native iOS app — and fixes
duplicate physical copies being mishandled on rescan.

## ✨ Features

- **MovieVault covers on barcode scan (PWA).** Scanning a disc now shows the
  MovieVault v2 cover in the PWA for both individual films and box-sets, matching
  native iOS. The `movievault_v2` plugin now forwards the DiscVault-served poster,
  and the PWA image guard recognizes the MovieVault poster route so the cover
  renders instead of a letter placeholder.
- **MovieVault owns the physical release's artwork.** A physical release has its
  own front cover, and the MovieVault identity source is now the authority on it.
  The poster survives on the movie, in `mediaUpdates`, and on the scan candidate
  the user picks from. All other enrichment (plot, cast & crew, runtime, ratings,
  trailers) still comes from the enrichment provider.
- **Scan-resolved covers are actually used.** The release-details resolver that
  carries a scanned barcode's artwork was registered but never called — it is now
  invoked, so the cover a scan resolves is fetched and surfaced. Posters without a
  checksum are served from MovieVault's stable anonymous asset URL rather than
  copied into the local cache (unverifiable bytes are never written to disk);
  checksummed catalog posters keep using the verified local cache.
- **Synced box-set covers survive and show in the library.** A box-set pushed
  from another client keeps its own cover instead of falling back to the first
  member film's poster, and the library card now shows the container's own primary
  artwork (previously only the detail page had it). A cover chosen or uploaded in
  DiscVault always wins.

## 🐛 Bug fixes

- **Duplicate physical copies on rescan.** `duplicate_copy` now short-circuits the
  whole identity ladder, so a second physical copy of the same film is handled
  correctly on rescan (iOS/PWA).
