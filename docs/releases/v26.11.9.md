# v26.11.9 — Titles file under their first real word, and an anonymous installation count

_Released: 2026-11-11_

## Highlights

**Since the previous stable version (v26.11.0)**, eight changes have reached production.
They were released to beta as 26.11.1 to 26.11.8.

- **The Library files titles the way a shelf does.** A title without a sort title is
  ordered without its leading article: *The Matrix* under **M**, *A Clockwork Orange*
  under **C**. English articles are skipped for everyone, and the articles of the
  language you use the app in are skipped too, such as *de*, *het* and *een* in Dutch. A sort
  title you typed is still used exactly as typed. The web app now puts a library in the
  same order as the iPhone app.
- **A new anonymous installation count.** Once a day the server tells
  `api.discvault.eu` that it is running: its version and the number of days since its
  previous report. Nothing else: no identifier, nothing about your collection or your
  accounts. It is **on by default**. The owner is told about it before the first report
  can leave, and it can be turned off in the app or with an environment variable. See
  the upgrade notes.
- **Unread notifications are visible.** A badge on the Profile entry in the sidebar, on the phone's
  tab bar and on the Notifications button now shows how many are waiting.
- **Single sign-on works with Authentik**, and with any other provider that publishes
  its endpoints with a trailing slash.
- Location backdrops display again, a header without a backdrop no longer shows a
  broken-image icon, and the migration wizard and collection dashboard load again.

**Read the upgrade notes before deploying.** There are no database migrations and no
plugin updates, but the installation count adds one environment variable to the Compose
files, with a default that needs no action.

## ✨ Features

- **Skip a leading article when ordering by name**
  ([#850](https://github.com/helmerzNL/DiscVault/pull/850)). Every name-sorted list now
  uses one ordering key, the same one the iOS app uses (App-Guidance
  `library-ordering.md` §1a): the sort title exactly as typed when there is one,
  otherwise the name with one leading article skipped. Two titles that are equal once the
  article is skipped are ordered by their full name, so *Matrix* and *The Matrix* keep a
  fixed order.
  - Which articles: English for every viewer, plus the language the app is displayed in.
    No other language's articles are skipped, so *Die Hard* stays under **D** except for a
    viewer who uses the app in German.
  - Where: the Library grid and list view (including the Title column and every
    tiebreak), a series' discs in grid, list and table view, and the Watchlist and
    Watched lists when sorted by name. The text on screen never changes.
  - A title filed in the wrong place is fixed with its sort title. Typing the title itself
    into the field pins it exactly where it reads.

- **Anonymous installation count**
  ([#844](https://github.com/helmerzNL/DiscVault/pull/844),
  [#845](https://github.com/helmerzNL/DiscVault/pull/845)). The count exists to estimate
  how much DiscVault is used, so that the MovieVault backend every installation looks
  discs up in can be scaled to match (App-Guidance ADR-0020).
  - Once per UTC day `next-worker` sends `POST https://api.discvault.eu/v2/presence` with
    the released version and the days since this server's previous accepted report.
    There is no instance id, hostname or user count. The days-since number is what lets
    the receiver count servers without one.
  - Only a released image reports; a source checkout or development build sends nothing.
    A server without an owner account sends nothing.
  - The owner is told first: on a new installation in the setup wizard while the owner
    account is created; on an upgraded server by a notice that stays on screen until the
    owner closes it or opens the setting.
  - Two off switches: **Preferences → Collectors** for the owner, and
    `DISCVAULT_INSTALLATION_COUNT=off` for the operator, which wins. Off means no request
    at all. `docs/installation-count.md` has the full detail.

- **Unread notification badge**
  ([#846](https://github.com/helmerzNL/DiscVault/pull/846)). The unread count every
  snapshot already carried had nowhere to show. It now appears on the Profile entry in the
  sidebar (on the icon when the sidebar is collapsed), on the Profile tab in the phone tab
  bar and on the Notifications button on the profile page. It is hidden at zero and stops
  at "99+".

## 🐛 Bug fixes

- **OIDC sign-in failed against Authentik**
  ([#843](https://github.com/helmerzNL/DiscVault/pull/843),
  [#842](https://github.com/helmerzNL/DiscVault/issues/842)). The endpoints a provider
  publishes in its discovery document were stripped of their trailing slash, so a
  provider with strict routing returned 404: first at the authorization endpoint, then at
  the token exchange (`token_exchange_failed`). The ID token's issuer would have been
  rejected next. Published endpoints now keep the spelling the provider gave them;
  configured values (`DISCVAULT_OIDC_ISSUER` and friends) stay canonical, so existing
  linked identities keep working with no migration and no re-linking. Not yet confirmed
  against a live Authentik instance.

- **The installation count notice went unseen**
  ([#845](https://github.com/helmerzNL/DiscVault/pull/845)). In 26.11.2 the notice sat
  unread in the inbox. It is now shown where the owner sees it, as described above.

- **The inbox behind the badge was stale, and the collapsed sidebar had no names**
  ([#847](https://github.com/helmerzNL/DiscVault/pull/847)). After a new notification the
  badge said 4 while the inbox showed the three cards it had loaded earlier; a changed
  count now makes the inbox fetch again. With the sidebar collapsed, the default on a
  desktop, entries had no accessible name; screen readers now hear the label again.

- **Location backdrops were refused, and a header without one showed a broken image**
  ([#848](https://github.com/helmerzNL/DiscVault/pull/848)). An uploaded location backdrop
  was stored, but its image was refused to every user. It is now shown to everyone who
  may see locations. A header without a backdrop no longer paints the browser's
  broken-image icon.

- **The migration wizard and the collection dashboard did not load**
  ([#849](https://github.com/helmerzNL/DiscVault/pull/849)). The migration wizard stopped
  at "Loading report..." with `pluginDisplayName is not defined`, and the collection
  dashboard's plugin administration had the same fault. Both pages now have the helper.

## ⚠️ Upgrade notes

**No database migrations.** This release adds no migration; a backup before upgrading
is still good practice, as always.

**No plugin updates.** No bundled plugin changed version, so nothing in **Admin → Plugins**
needs checking for this release.

**The installation count starts after the upgrade, unless you switch it off.** The first
time the owner opens the app after upgrading, a notice explains the count and stays on
screen until they close it or open the setting. To have it off from the very first
start, set `DISCVAULT_INSTALLATION_COUNT=off` before deploying (see *Deployment files*);
then no request is made at all, whatever the owner setting says. A server without an
owner account reports nothing.

**Your Library may look reordered.** Titles that start with an article now file under
their next word. That is the intended change. A title that should stay where it was can
be pinned with its sort title. While a very large library is still loading, titles that
start with an article can move up as the rest arrives; this settles once loading
finishes.

**No manual reload is required.** No preference is overridden, and nothing that was on is
turned off.

### Deployment files

- **One new environment variable: `DISCVAULT_INSTALLATION_COUNT`**, default `on`. An
  existing deployment keeps working untouched: with the variable absent, the default
  applies and the count runs.
  - **Compose** (`app/deploy/next/docker-compose.yml` and `app/docker-compose.next.yml`):
    both `next-api` and `next-worker` gain
    `DISCVAULT_INSTALLATION_COUNT: ${DISCVAULT_INSTALLATION_COUNT:-on}`. `next-worker`
    sends the report; `next-api` reads the variable only to show the owner that the
    operator switched it off. If you keep your own Compose file, add the line to **both**
    services, or the owner's switch looks like the one in charge.
  - **`.env`**: add `DISCVAULT_INSTALLATION_COUNT=off` only if you want the count off.
    `on` (or leaving it out) keeps it on. `false`, `0` and `no` also mean off.
  - **Unraid**: the template gains an *Anonymous installation count* variable under the
    advanced settings, default `on`.
- **One new outbound request.** `next-worker` makes at most one accepted
  `POST https://api.discvault.eu/v2/presence` a day; after a failure it waits at least an
  hour, tries at most six times a day and honours `Retry-After`. A firewall or egress
  policy that blocks it only stops the count; nothing else depends on it.
- **No size, rate or timeout limit changed in this release**, so nothing running in front
  of DiscVault (a reverse proxy, an ingress, a CDN) needs adjusting.
