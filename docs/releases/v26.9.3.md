# DiscVault v26.9.3

DiscVault v26.9.3 promotes the complete beta train since v26.7.2. It changes what
DiscVault holds: not a shelf of films, but a shelf of physical releases. A
television series is now a kind of its own, with its seasons and episodes, and a
release can be described disc by disc rather than as a single row. MovieVault
became a two-way relationship — corrections you make travel back to the
catalogue, and the catalogue answers with far more than it used to.

## Highlights

- **Television series are a first-class kind.** A series has its own page, hero
  and URL, groups in the Library, carries the seasons you own, and — behind the
  Collectors switch — its episodes, each individually markable as watched.
  TheTVDB joins TMDb as a source.
- **A release is described disc by disc.** A box set is no longer one row of
  technical facts. Each disc carries its own, and the release row is derived as
  the union of them, so "what audio does this set have" is answered by the set
  rather than by whichever disc was entered first.
- **Imports stop overwriting your data.** A collection import now *fills* an
  empty field and leaves an existing value alone. Only a field you confirm in
  the review wins — and every product code a row carries is kept, instead of all
  but one being dropped.

## Multiple discs per release

- The individual discs inside a release can be described — type, role, and their
  own technical facts. Adding the first disc promotes the release's existing
  details onto Disc 1 rather than asking you to retype them.
  ([#582](https://github.com/helmerzNL/DiscVault/pull/582),
  [`fbdf6a0`](https://github.com/helmerzNL/DiscVault/commit/fbdf6a0);
  [#585](https://github.com/helmerzNL/DiscVault/pull/585),
  [`d083743`](https://github.com/helmerzNL/DiscVault/commit/d083743))
- **The release row is the union of its discs.** HDR, screen ratios, regions,
  video codecs, audio tracks and subtitles are collected across every disc, in
  the discs' own order. Resolution is the exception: it takes the best a disc in
  the box offers, so a 4K disc packaged with a Blu-ray is a 2160p release.
  ([#609](https://github.com/helmerzNL/DiscVault/pull/609),
  [`a647606`](https://github.com/helmerzNL/DiscVault/commit/a647606);
  [#610](https://github.com/helmerzNL/DiscVault/pull/610))
- Releases that already had discs before that rule existed were converged onto
  it, and a client write to a field the discs own is refused rather than silently
  derived over.
  ([#610](https://github.com/helmerzNL/DiscVault/pull/610),
  [#612](https://github.com/helmerzNL/DiscVault/pull/612))
- The catalogue's disc breakdown fills a release that has none, and a release the
  catalogue does not hold can be offered to it.
  ([#607](https://github.com/helmerzNL/DiscVault/pull/607),
  [`06bf0b3`](https://github.com/helmerzNL/DiscVault/commit/06bf0b3);
  [#608](https://github.com/helmerzNL/DiscVault/pull/608))
- Discs travel in both directions over sync.
  ([#587](https://github.com/helmerzNL/DiscVault/pull/587),
  [`a7b138b`](https://github.com/helmerzNL/DiscVault/commit/a7b138b))

## MovieVault

- **Contribute a correction back to the catalogue.** A working Upload button
  sends a field correction, the contribution switch sits where the app can reach
  it, and a contribution reports what became of it instead of vanishing.
  ([#551](https://github.com/helmerzNL/DiscVault/pull/551),
  [`8716ad1`](https://github.com/helmerzNL/DiscVault/commit/8716ad1);
  [#553](https://github.com/helmerzNL/DiscVault/pull/553);
  [#554](https://github.com/helmerzNL/DiscVault/pull/554);
  [#555](https://github.com/helmerzNL/DiscVault/pull/555))
- Before proposing, DiscVault checks the catalogue and lists exactly what it is
  about to send — box sets included — and announces a verdict afterwards.
  ([#556](https://github.com/helmerzNL/DiscVault/pull/556);
  [#557](https://github.com/helmerzNL/DiscVault/pull/557))
- The whole technical description can be proposed, not just single fields.
  ([#596](https://github.com/helmerzNL/DiscVault/pull/596))
- **Typed product identifiers.** A pressing carries several codes at once — an
  EAN for Europe beside a UPC for North America, an ASIN, a catalogue number.
  They are stored as typed identifiers rather than all but one being discarded,
  and the type is derived from the digits rather than from whatever a column
  header claims.
  ([#559](https://github.com/helmerzNL/DiscVault/pull/559),
  [`40a7745`](https://github.com/helmerzNL/DiscVault/commit/40a7745))
- The catalogue contract advanced from distribution-4 to **distribution-6**, the
  version that carries per-disc breakdowns. Along the way: the video profile and
  structured audio/subtitle tracks, release packaging, work type, and the seasons
  a release covers.
  ([#595](https://github.com/helmerzNL/DiscVault/pull/595),
  [`81cbabb`](https://github.com/helmerzNL/DiscVault/commit/81cbabb);
  [#597](https://github.com/helmerzNL/DiscVault/pull/597);
  [#603](https://github.com/helmerzNL/DiscVault/pull/603))
- MovieVault v2 is the default metadata source, and a lookup says which route
  resolved it, visible in the audit log and App Admin.

## Imports

- **An import fills a field; it no longer overwrites one.** A value already on a
  film survives, and only a blank one is filled from the file. This matters
  because rolling an import back deletes only the films it *created* — a film
  that was merely updated had nothing to restore from. A Blu-ray.com row could
  retitle a film to "Bohemian Rhapsody 4K" and date *Back to the Future* to 2012,
  the year of the disc. A field you confirm in the review still wins, and only
  that field.
  ([#570](https://github.com/helmerzNL/DiscVault/pull/570),
  [`9bb4bc8`](https://github.com/helmerzNL/DiscVault/commit/9bb4bc8))
- Every product code an imported row carries is kept, including the `ASIN` column
  a Blu-ray.com export was losing. A code another film already holds is skipped
  rather than failing the row.
  ([#570](https://github.com/helmerzNL/DiscVault/pull/570))
- Blu-ray.com imports describe the film rather than the pressing: a trailing `4K`
  or `UHD` title token becomes a format, and a row without a year or release date
  no longer fails the whole import.
  ([#540](https://github.com/helmerzNL/DiscVault/pull/540),
  [`0208973`](https://github.com/helmerzNL/DiscVault/commit/0208973);
  [#550](https://github.com/helmerzNL/DiscVault/pull/550))

## Performance and resilience

- Metadata refreshes itself when you open a library entry, a movie or a person,
  with visible feedback, instead of blocking the page on live provider calls.
  TMDb person data is cached.
  ([#505](https://github.com/helmerzNL/DiscVault/pull/505))
- A cold load no longer runs the same expensive snapshot query three times, and a
  database outage shows a friendly offline page.
  ([`0f73e23`](https://github.com/helmerzNL/DiscVault/commit/0f73e23))
- A database blip no longer crash-loops the worker, and `next-api` bounds how
  long a single statement or lock wait may take, so a stuck database fails fast
  instead of hanging until gunicorn kills the worker.
  ([`13641dd`](https://github.com/helmerzNL/DiscVault/commit/13641dd),
  [`a6d8e23`](https://github.com/helmerzNL/DiscVault/commit/a6d8e23))
- Library hydration restarts after the app reloads its own snapshot, instead of
  giving up forever, and a stalled hydration has a way back.
- A metadata refresh no longer surfaces as "DiscVault is temporarily offline",
  and a source that failed is no longer reported as a source that found nothing.
  ([#571](https://github.com/helmerzNL/DiscVault/pull/571),
  [#578](https://github.com/helmerzNL/DiscVault/pull/578))

## Upgrade notes

- **Migrations 048 through 076** run at startup. No manual step.
- **`cryptography` moves from 48.0.1 to 50.0.0.** Pull the new image, or
  reinstall from `app/backend/requirements.txt` if you run from source.
- **Three new environment variables, all optional and all defaulted**, so an
  existing `.env` keeps working untouched:
  - `DISCVAULT_NEXT_DB_WAIT_TIMEOUT` — seconds `next-api` and `next-worker` keep
    retrying while PostgreSQL refuses connections. Default `300`.
  - `DISCVAULT_NEXT_API_STATEMENT_TIMEOUT_MS` — default `10000`.
  - `DISCVAULT_NEXT_API_LOCK_TIMEOUT_MS` — default `5000`.
    Both apply to `next-api` only; `next-worker` is intentionally unbounded so
    imports and MovieVault syncs are not cut off.
- **If you run your own Compose file** rather than the tracked one, add these two
  mappings to the `next-api` service, or the timeouts above will never reach it:

  ```yaml
  DISCVAULT_NEXT_API_STATEMENT_TIMEOUT_MS: ${DISCVAULT_NEXT_API_STATEMENT_TIMEOUT_MS:-10000}
  DISCVAULT_NEXT_API_LOCK_TIMEOUT_MS: ${DISCVAULT_NEXT_API_LOCK_TIMEOUT_MS:-5000}
  ```

- **`depends_on` changed from `service_healthy` to `service_started`** for
  `next-api`, `next-worker` and `next-mcp` in the tracked Compose files. Gating
  on health let a slow or recovering database abort the whole `up`; each service
  now waits for PostgreSQL itself and the stack converges on its own. Mirror this
  in your own Compose file to get the same behaviour.
- **TheTVDB** is configured from the plugin settings inside the app — API key,
  optional PIN, and a three-letter language code. There is no environment
  variable for it, and nothing to add before deploying.
- User-facing changes include complete translations across all supported locales.
